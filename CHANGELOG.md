# Changelog

Each release of the registry, newest first. A change to an item's interface is marked **interface change**.

## 0.13.0 — unreleased

The system's code names now say Kuiper, as the system does. Before you update, read [Upgrade to 0.13.0](https://pluto-systems-design.claygendron.workers.dev/changelog/0.13.0/upgrade/): rename your own uses of the four old keyframe names first, then update, and know what keeps working until 0.14.0. The theme's page moved to `/components/kuiper-theme/`; its old address redirects.

- `kuiper-theme`: **interface change.** Renamed from `pluto-theme`. Until 0.14.0, `add pluto-theme` still installs `kuiper-theme`, through an alias entry with no files of its own; the alias is removed in 0.14.0. The theme's four keyframes are renamed, and the old names are removed now, with no alias, so **rename your own uses of the four old names before you update the theme**: `pluto-enter`, `pluto-exit`, `pluto-mark-dock` and `pluto-mark-fade` become `kuiper-enter`, `kuiper-exit`, `kuiper-mark-dock` and `kuiper-mark-fade`. Uses not renamed first leave your built CSS silently. Look in `app.css`, in components' `<style>` blocks, in inline `style` attributes, in `animation-name` declarations and in scripts. After the update, delete the four dead `@keyframes pluto-…` rules from `app.css`: the CLI adds the new rules and never deletes the old. The `animate-enter` and `animate-exit` classes, and every variable and utility, keep their names. Its title is "Kuiper theme". The token file is now `tokens/kuiper.tokens.json`, with no copy at the old path `tokens/pluto.tokens.json`; tagged URLs keep the old path.
- `theme`: **interface change.** The stored choice's key is `kuiper-theme`, was `pluto-theme`. On a visitor's first load after the update, a `light` or `dark` stored under `pluto-theme` is carried over to `kuiper-theme` before first paint, so the choice is kept, and `pluto-theme` is removed; the carry-over goes in 0.14.0. A stored value other than `light` or `dark` now means the system in the head script too, as it already did in the store. `THEME_KEY` reads `kuiper-theme`, and `THEME_SCRIPT` changes, so an app that allows the head script by a Content Security Policy hash updates the hash; an app that passes `nonce` is unaffected. A new file, `stored.ts`, holds the read. Rolled back to 0.12.0 after the update, visitors' choices reset once.
- `field`, `input`, `textarea`, `checkbox`, `switch`, `native-select`, `input-otp`, `input-group`, `radio-group`: **interface change.** The context keys are `kuiper:field` and `kuiper:field-set`, were `pluto:field` and `pluto:field-set`. Until 0.14.0, `field` sets both names, and the eight controls read the new name, then the old, so an old `field` with a new control, or the reverse, still wires the label, the description and the error. `FIELD_CONTEXT_KEY` and `FIELD_SET_CONTEXT_KEY` read `kuiper:field` and `kuiper:field-set`; an app's own control that imports them needs a 0.13.0 `field`, so update `field` first. The label's key is `kuiper:field-label`, was `pluto:field-label`, set under both names until 0.14.0.
- `tooltip`, `item`, `popover`, `accordion`: **interface change.** Their context keys are `kuiper:tooltip`, `kuiper:item-group`, `kuiper:popover` and `kuiper:accordion-item`, were `pluto:tooltip`, `pluto:item-group`, `pluto:popover` and `pluto:accordion-item`. Each is set under both names until 0.14.0, for an app's own code that reads one.
- `highlighter`: **interface change.** The Shiki theme is registered as `kuiper-code`, was `pluto-code`, and `shikiTheme.name` reads `kuiper-code`, with no alias. Code that passed `pluto-code` to Shiki itself passes `kuiper-code`.
- `button-group`: new, a `registry:ui`. A `role="group"` of buttons, `attached` (joined, for secondary buttons and menu triggers) or `spaced` (a wrapping row that stacks below 640 px), horizontal or vertical. Each button is its own Tab stop. Name it with `aria-label`. It depends on `button`.
- `link`: new, a `registry:ui`. An `<a href>`, always underlined, thicker on hover, in the primary colour or `variant="inherit"`. `standalone` gives a 24 px target; `newTab` merges `noopener noreferrer` into `rel` and adds an icon and "(opens in a new tab)" for screen readers, and a `target="_blank"` passed directly is treated the same; `visited` shows visited links in the text colour. `linkVariants` styles a plain `<a>`, and takes `class`. It depends on `phosphor-svelte`.
- `progress`: new, a `registry:ui`. A native `<progress>` on the muted track with a primary fill, or a destructive one, as `meter` is drawn. Name it, pass `valuetext`, and write the numbers beside it; announce the start and the end with `status`. No indeterminate form: use `spinner` for a wait of unknown length.
- `toast`: new, a `registry:ui`. `toast("Saved")`, `toast.success`, `toast.info`, `toast.caution`, `toast.error`, `toast.loading` and `toast.promise` raise a short message at the top end of the page, under a declared sticky bar; `toast.dismiss` closes one or all. Mount `<Toaster />` once, in the root layout (`app-shell` does). Two hidden announcers, present from the first render and on one schedule, speak each toast: errors interrupt, the rest wait their turn, and a success raised beside an error is spoken after it. The visible stack is never live, and no toast is a tab stop; F8 moves focus to the list and back, and Escape in a toast dismisses it. A toast never covers the element that has keyboard focus: it steps aside until focus moves, and the stack's count line says "1 hidden". Success and info leave after at least 6 s, longer for longer text, and pause on hover, on focus, while the window is in the background and while a modal is open; errors, cautions, loading toasts and any toast with an action wait to be dismissed. `duration: Infinity` keeps a toast. `timers="off"` turns timing off: to meet WCAG 2.2.1, bind it to a setting the person can reach first, or keep every timed message on the page too. Three show at once (one below 640 px); errors go first. A success or info toast survives one navigation; call `toast.navigating()` and `toast.navigated()` from your root layout if you do not use `app-shell`. A toast raised while a modal is open shows when it closes. Text only: no custom components. It depends on `status`, `button` and `spinner`, and on `phosphor-svelte`.
- `app-shell`: **interface change.** The layout mounts `<Toaster />` right after the skip link, and calls `toast.navigating()` and `toast.navigated()` in `beforeNavigate` and `afterNavigate`. It now depends on `toast`. If you moved the layout into your routes, add the two imports and the three lines by hand (the upgrade guide shows them). If your app mounts another toaster, such as shadcn-svelte's `sonner`, remove it, so two corners do not compete. To meet WCAG 2.2.1, bind the toaster's `timers` to a person's setting, as the layout's comment shows. No prop or class changes. Update with `add app-shell`.
- `pagination`: new, a `registry:ui`. A `nav` named "Pagination", holding Previous, the pages and Next. Pass `href={(page) => …}` and every page is a link; leave it out and they are buttons, with `bind:page` and `onpagechange`. The current page has `aria-current="page"` and a border; each page is named "Page N". Previous is omitted on the first page and Next on the last, and the row keeps its width. In button mode a hidden status says "Page 6 of 12", focus stays on the page you pressed, and if the control you pressed is gone, focus moves to the current page, or to the other end control when narrow. Below the width the full row needs, "Page 5 of 12" replaces the page list. In a row beside other content, give it `flex-1`. Nothing renders for one page. It depends on `button` and `status`, and on `phosphor-svelte`.
- `search-field`: new, a `registry:ui`. An `input type="search"` in an `input-group`, with a magnifier and a Clear button that shows while there is text and returns focus to the input. Escape clears a filled field and stops there, so a dialog around it stays open; on an empty, disabled or read-only field it passes on. Pass `results` and the field speaks it once typing pauses for 750 ms and the count is for what is typed now: set `results` to `undefined` while a server's count is on its way, and pass `resultsFor`. The spoken count stays until the field next changes: a keystroke, Clear or Escape empties it. So a count waits for a screen reader that comes to it late, one more letter with the same count is heard again, and no count stays for a query that is gone. Name it with a label. The browser's own cancel button is hidden with `display: none`, so the field shows one clear button in every browser, GNOME Web and other Linux WebKit browsers among them. It depends on `input-group` and `status`, and on `phosphor-svelte`.
- `tag`: new, a `registry:ui`. `Tag` is removable (`onremove`, a 24 px button named for the tag, such as "Remove Design", and Delete or Backspace) or pressable (`bind:pressed`, `aria-pressed`, a check while pressed). `TagGroup` is a named list that moves focus to the next tag control after a removal, then the previous, then `fallback`, then itself. Emptied, the list renders its `aria-label` as visually hidden text, not an item, so a screen reader in browse mode has its name to speak when it takes focus; without a `fallback`, name it with `aria-label`. It depends on `button`, and on `phosphor-svelte`.
- `kuiper-theme`: not an interface change. The token source is now DTCG 2025.10, the W3C Design Tokens format: a resolver, `tokens/kuiper.resolver.json`, combines the tokens both schemes share with the light or the dark scheme's file, and every role's job is in it, as its `$description`. The CSS an app gets is unchanged, byte for byte.
- **New:** the tokens are published as plain CSS variables and as DTCG files. Each file is on the design site at `/v0.13.0/r/tokens/<name>` (`/r/tokens/<name>` for the latest release), and from GitHub at the release's tag. `kuiper.css` is every token as a custom property, for a stack without Tailwind. `kuiper.resolver.json` combines `kuiper.tokens.json` with `kuiper.light.tokens.json` or `kuiper.dark.tokens.json`. `kuiper.flat-light.tokens.json` and `kuiper.flat-dark.tokens.json` are each scheme in one file, for a tool that cannot read a resolver. `kuiper.removed.json` records every name that shipped and is gone, with what replaces it. Copy a file into your app; never link to it at run time. From 0.13.0 the DTCG token paths, the 48 primitives included, are an interface: a path renamed or removed is listed in `kuiper.removed.json` (constitution §6).
- **Every prop described:** every component page's API table now says what each prop does, and shows a prop's default under its description. The words are doc comments in each item's source, so your editor shows them on hover too; `class`, `ref` and `children` are described on the design site, from each part's markup, not in the source.
- `utils`, `four-dot`, `theme`, `read-token`, `liquid-glass`, `button`, `tooltip`, `toggle`, `card`, `separator`, `item`, `tabs`, `collapsible`, `avatar`, `popover`, `alert`, `alert-dialog`, `badge`, `empty`, `spinner`, `field`, `input`, `textarea`, `input-group`, `native-select`, `checkbox`, `radio-group`, `switch`, `input-otp`, `code-block`, `code-editor`, `highlighter`, `use-highlighted-code`, `code-languages`, `chart`, `dropdown-menu`, `sheet`, `dialog`, `breadcrumb`, `sidebar`, `is-mobile`, `message-log`, `message`, `marker`, `composer`, `stage`, `stage-card`, `marketing-bar`, `stage-hero`, `proof-band`, `live-console`, `name-strip`, `cta-band`, `marketing-footer`, `hero`, `sign-in`, `sign-up`, `page-states`, `settings`, `app-shell` and `chat`: doc comments on every prop; no interface change.
- `toggle-group`: doc comments on every prop; no interface change; `ToggleGroup`'s `value` accepts the same values, and an editor now shows its type as `string[] | (string[] & string) | undefined` in the multiple form.
- `accordion`: doc comments on every prop; no interface change; `Accordion`'s `value` accepts the same values, and an editor now shows its type as `string[] | (string[] & string) | undefined` in the multiple form.
- `dropdown-menu`: **Escape's behaviour changes**; no prop is added or removed. In a submenu, Escape now closes that submenu alone and returns focus to the item that opened it, as ArrowLeft does and as the WAI-ARIA menu pattern asks; the menu stays open, and a second Escape closes it and returns focus to the trigger. Before, Escape in a submenu closed the whole menu. `DropdownMenuSubContent`'s `escapeKeydownBehavior` now defaults to `"close"` (bits-ui's default is `"defer-otherwise-close"`); pass that value to have the outermost menu take Escape again. Your own `onEscapeKeydown` is still called first, and `preventDefault()` there keeps the submenu open.
- `sidebar`: no interface change. `SidebarContent`, the scroll box between the header and the footer, now manages its own Tab stop. While it holds a link, an enabled control or any other element that takes a Tab stop, it has `tabindex="-1"`, so Firefox no longer makes an overflowing box an extra, unnamed stop before its first row. While it holds only text, it has `tabindex="0"`, so a keyboard user can still reach it and scroll it with the arrow keys, in every browser (WCAG 2.1.1). It reads its contents after mount and again whenever they change. A `tabindex` you pass wins. No prop, slot or class changes.
- `use-highlighted-code`: no interface change. The hook loads nothing while its code is empty: the tree-sitter runtime and the language's grammar load with the first non-empty code, not at mount, so a block that waits for its first chunk costs no grammar until then. Emptying the code again unloads nothing. `settled` is true while the code is empty, since nothing then loads. A `CodeBlock` given a `language` and empty `code` fetches nothing.
- `code-editor`: no interface change. The editor now binds Enter and Shift+Enter to CodeMirror's `insertNewline`, at the lowest precedence. Before, an editor given no `extensions`, or a setup with no Enter binding, left the key to the browser, and in GNOME Web and other Linux WebKit browsers one Enter at a line's end added two lines. `pythonSetup()`, and any keymap of your own, still binds Enter first. In every browser, the editor now handles Enter's keydown itself and prevents its default. An app that watched Enter in its own `domEventHandlers`, or relied on the browser's default, binds Enter in a keymap of its own, which still wins. Read-only and disabled editors still ignore Enter. No prop changes.
- `code-block`: **the copy button keeps its name**; no prop, slot or export changes. After a copy, the button is still named "Copy code" and shows a check for two seconds, and the status beside it says "Copied", the one place it is said. Before, the name became "Copied" too, and NVDA read "Copied" twice. A test of your own that looked for a button named "Copied" reads the status's text instead. Update with `add code-block`.
- `error-summary`: a new optional prop, `attempt`; nothing to change. Raise it by one on each failed submit, and the summary's content is rendered anew, so a screen reader announces it again even when the errors are the same. Leave it out and a summary is announced when it appears or its text changes, as before. Update with `add error-summary`.
- `sign-in`, `sign-up`, `settings`: no interface change. Each form now raises the summary's `attempt` on every failed submit, so a second failure with the same errors is announced again. Update with `add sign-in`, `add sign-up` or `add settings`; each brings the new `error-summary`, which must be overwritten too: a form that keeps its old `error-summary` passes `attempt` as a plain attribute and is not announced again.

## 0.12.0 — 2026-11-15

Code is highlighted by tree-sitter with this system's own queries, in code blocks and in the editor alike, and coloured in the Tombaugh palette, after the guide Meridian: keywords violet, functions blue, types navy, strings green, numbers yellow, constants orange, meta plum, specials red, comments grey and upright. Every colour reads 4.5:1 or more on the code ground and the active line in both themes, and dark colours sit between 6.5 and 9.5 on the dark code ground. Numbers and constants are close in light mode for a reader with protanopia; numbers are digits and constants words. In light mode code sits on white, lighter than the page, and every code block and editor is edged by the hairline. The brand's yellow is yellower and lifted in dark: `#E2B000` in light, `#F8D874` in dark, in place of `#F19E20`.

The design system is named the Kuiper Design System. Its code names are unchanged in this release: the `pluto` registry, the `pluto-theme` item, the `pluto:` context keys and the token file keep their names, and 0.13.0 renames them, with a migration guide.

The design site, the Kuiper Design System's, is new, its home page headed "Design with Kuiper": how to build with the system, and the brand. It serves this registry at its own versioned path, `/v0.12.0/r`, beside GitHub's raw files, so an app installs from either; every component has a page that shows it live in both themes, with its API, the files you own and how to install it. Every page also has a Markdown twin at `index.md`, listed in `llms.txt`. The site also has Start guides, from an empty app to a first part; Brand pages on the mark, colour, type, surfaces, motion, imagery, voice and products, with the mark and the lockup as SVG downloads drawn from the token file; and Foundations pages that explain every token by its job, with its measured contrast. Every page but home keeps a left navigation of its section, and a phone menu holds every page; a component page shows the part first, then how to install it, says when it was last updated, and every page links to suggest a change on GitHub; search finds a part by the start of a word or by another system's name for it; and the Components index shows a picture of every part.

- `pluto-theme`: **interface change.** The code map is Meridian's roles. `--code-text` replaces `--code-foreground`, and code's body is now its own ink (`#25292F` light, `#D9DFE8` dark), not the page's foreground. `--code-meta` and `--code-special` are new. `--code-escape`, `--code-builtin`, `--code-tag`, `--code-property`, `--code-decorator`, `--code-self` and `--code-invalid` are removed, with their `text-code-*` utilities. `--code-comment`, `--code-keyword`, `--code-function`, `--code-type`, `--code-string`, `--code-number`, `--code-constant`, `--code-link`, `--code-inserted`, `--code-deleted` and `--code-changed` keep their names and take new colours. The theme roles `syntax-amber`, `syntax-purple`, `syntax-teal` and `syntax-cyan` are removed; `syntax-orange` takes a new colour; `syntax-violet`, `syntax-blue`, `syntax-navy`, `syntax-green`, `syntax-yellow`, `syntax-plum`, `syntax-red`, `syntax-grey` and `syntax-ink` are new. The inline-code chip's text takes `--code-text`. The code ground and the active line have theme roles of their own, `--syntax-ground` and `--syntax-active-line`. `--code-background` and `--code-active-line` keep their names and now name them. In light mode the code ground is white (`#FFFFFF`), not `wash` (`#E9E5DB`), and the active line is the page canvas (`#F3F0E8`), not white; dark mode's grounds are unchanged. A new utility, `scrollbar-code`, draws a scroll box's track in the code ground; inside an ink surface that track is the surface, in both page themes. Inline code, a `code` element not inside a `pre` or a heading, is now a chip on the code ground with the hairline edge, the case radius, 4 px of side padding and the code body colour (the link colour inside a link), in both themes; the line height does not change, and a chip that wraps keeps its edge on each line. `kbd` and `samp` are unchanged. A class an app sets on its own `code` wins for the properties it sets, since the rule is in the base layer; the hairline, the radius, the side padding and the code colour still apply unless a class sets them too. The chip adds 10 px to inline code's width (4 px of padding and a 1 px edge on each side), so an unbreakable inline token in a tight column can widen that column by as much; give the `code` `wrap-anywhere`, or its container `break-all`. The code-ground change itself renames and removes nothing; every rename and removal in this bullet is the code map's. An app's own class named `scrollbar-code` would take the theme's rule; rename it before updating. An app that painted its own surfaces with `--code-background` now gets white in light mode. The brand yellow is `#E2B000` in light and `#F8D874` in dark, in place of `#F19E20` in both: the mark's third dot (`--mark-3`), `field-3`, `--chart-3` and the `--caution` fill, with ink on it (9.53:1 light, 13.75:1 dark). A new role, `--caution-text` (`#806200` light, `#F8D874` dark), is the yellow for text, 4.5:1 or more on the page, a card and `muted`. In light `--chart-3` stays under 3:1 on the page and on cards (1.76, 2.01) and is labelled directly, as before. The light `--caution` fill drops the same way: the badge's fill against the page goes from 1.91 to 1.76 and the alert's bar on its card from 2.17 to 2.01; both name their state in words. The yellow renames nothing an app reads; the `amber` primitives are renamed `yellow`, and primitives never reach an app. In dark mode, code's `type` colour (`--syntax-navy`) is `#A8C0D8`, so a type stands further from a function name; it reads 7.81:1 on the dark code ground. Every letter spacing is now the font's default: the four tracking tokens (`--tracking-display`, `--tracking-section`, `--tracking-eyebrow`, `--tracking-mark`) and the four expressive steps' `--type-display-tracking`, `--type-section-tracking`, `--type-proof-tracking` and `--type-poster-tracking` all read `0em`, so headings, eyebrows and the lockup's word are no longer tightened or widened. The variables and the `tracking-*` utilities keep their names, so no class breaks; an app that wants the old spacing sets its own `letter-spacing`. The old values were: `--tracking-display` −0.03em, `--tracking-section` −0.02em, `--tracking-eyebrow` 0.08em, `--tracking-mark` −0.04em; `--type-display-tracking` −0.045em, `--type-section-tracking` −0.035em, `--type-proof-tracking` −0.04em, `--type-poster-tracking` −0.05em. The rule a bar marked `data-sticky-bar` brings is now a default: it sits in `@layer base`, as `:where(html:has([data-sticky-bar]))`, so an app's own `scroll-padding-top` wins over it, in any layer or as a `scroll-pt-*` class on `html`. With none set, the page still gets `--size-bar`. After updating, delete the old unlayered `html:has([data-sticky-bar]) { scroll-padding-top: var(--size-bar); }` from your stylesheet: the CLI does not remove it, and while it stays it overrides your own value.
- `code-block`: **interface change.** Its body text takes `--code-text`, and its tokens the new role classes; no token is bold. `CodeBlockContent` sets `data-highlight` to `"pending"` or `"settled"`. No prop, slot or export changes. The root draws a 1 px `border-border` on each side. At the same content it is 2 px taller. Where it fills its container, its width is unchanged and its code area is 2 px narrower, so a line that just fit may now scroll. Where it sizes to its content, as in a chat bubble, it is also 2 px wider. A fixed height keeps its size and shows 2 px less code. Its scroll track is the code ground. The advice to pass `class="bg-muted"` to keep an inset is withdrawn: code on `muted` does not meet AA with this release's colours.
- `code-editor`: **interface change.** Colour comes from the highlighter, through `codeHighlighting(language)`, so the editor colours code exactly as the code block does. Until the highlighter loads (the runtime, about 115 kB gzipped, and the language's grammar, once per page) the editor shows plain text, as its prerendered fallback does; before, CodeMirror coloured it on mount. Its text, its caret and its prerendered text take `--code-text`. `codeHighlight`, `pythonLanguageConfigured` and `pythonRoles` are removed, and `pythonSetup()` now pairs `pythonLanguage` (for structure) with `codeHighlighting("python")`; it keeps its name and return type. An app that imported the removed exports: in place of `pythonLanguageConfigured`, use `pythonLanguage` from `@codemirror/lang-python` with `codeHighlighting("python")`; drop `pythonRoles`; in place of `codeHighlight`, add `codeHighlighting(language)` for the editor's language. The item now depends on `highlighter`. No prop or slot changes. The root reads the code ground (`bg-code-background`) in place of `bg-muted` and draws the same hairline, with the same change of size as `code-block`. Its focus ring stays 2 px outside its edge. Its scroll track is the code ground. Prerendered, it is the colour it has once mounted. Separately, comments reworded to drop internal references, and one corrected: the theme file reads four `@theme inline` names, not five.
- `highlighter`: **interface change.** tree-sitter (`web-tree-sitter` and 19 grammar packages, now `dependencies` of the item) highlights 21 languages at prerender and in the browser; Shiki highlights Markdown, diff, SQL, Swift and Dockerfile, and any language whose grammar is removed or fails to load. `highlightCode` and the `HighlightedLine` type are unchanged; `highlightCode` now waits for any grammar the code embeds. `loadHighlighter` returns a highlighter whose `highlight(code)` is asynchronous and whose `session(code)` updates incrementally (`update(code, changes)`, `onChange`, `settled`), and takes no grammar state. `tokenClass` takes a role; `tokenClasses` is replaced by `roleClasses`; `codeTheme` is renamed `shikiTheme`. Tokens are never bold. The packages take about 350 MB on disk, and every client build carries their 20 grammar files and the runtime, about 23.5 MB raw (2.15 MB gzipped); a page fetches only the runtime and the grammars it shows. To keep fewer languages, delete their rows in `highlight/languages.ts` and remove their packages; they fall back to Shiki. A strict Content Security Policy needs `'wasm-unsafe-eval'`. Separately, comments reworded to drop internal references.
- `code-languages`: each language keeps CodeMirror's indentation, brackets and behaviour, and takes its colour from the highlighter. Its exports are unchanged. Comments reworded to drop internal references; no interface change.

- `kbd`: **interface change.** A key now sits on the code ground (`bg-code-background`: white in light mode, `#2C2821` in dark), in place of `bg-muted`, with its hairline edge and muted text kept. It no longer sets `pointer-events-none` or `select-none`, so its text can be selected and copied. A click on a key inside a button still reaches the button. An app that installed `kbd` and wants the old ground passes `class="bg-muted"`; to keep a key unselectable, pass `class="select-none"`.
- `error-summary`: **interface change.** `role="alert"` moves from the summary's root to a new inner element, `data-slot="error-summary-content"`. The title, the message and the list move inside it, so a class passed to the root that targeted its children (`*:…`, `[&>h2]:…`) must now target that element. The root, the element `ref` binds and the form focuses, has no role; it keeps `tabindex="-1"`. Do not pass it a `role`. `announce` sets the inner element's role and still defaults to true. Code or tests that found the alert on the root, or expected `getByRole("alert")` to be the focused element, should look for `[data-slot="error-summary-content"]`. A link still focuses its field, and leaves the page where it is when the field and its label are already in view and uncovered.
