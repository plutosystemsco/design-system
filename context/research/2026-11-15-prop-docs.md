# Prop docs: how systems describe props, and how Svelte 5 tooling shows them

- **Status:** a research memo. It commits us to nothing. Corrected 2026-11-15, after `023`'s specification review: §8 holds the corrections and governs where it differs.
- **Date:** 2026-11-15
- **Author:** the spec author for `023`, for the design lead
- **Question:** Where should Kuiper's prop descriptions live so that the API tables fill in and an app's editor shows them? What counts as a prop? How many need writing? And what would a test that every `var(--x)` in an item resolves have to know?
- **What would answer it:** a count of today's API rows by where each comes from; a run of Svelte's own tooling on a typed and an untyped `$props()`; how Carbon, Primer, Spectrum, Radix Themes, shadcn-svelte and bits-ui keep their prop descriptions; a census of the `var()` references in item files.
- **What it blocks:** [`023`](../specifications/023-prop-doc-comments.md).

Every claim is labelled **EXECUTED** (run here, on 2026-11-15, read-only, over the working tree before `020`), **READ** (a source says so, linked, read 2026-11-15) or **INFERRED** (our reasoning). Measurement scripts lived in the session scratchpad. They imported `src/lib/site/api.server.ts` and wrote nothing to the repository.

**Terms.** An **API row** is one line of a component page's API table, as `apiTables()` in `api.server.ts` returns it. A **doc comment** is a `/** … */` block that TypeScript attaches to a declaration. A **pass-through** is a prop that an item names in its `$props()` destructuring but does not declare in its own type: it comes from `svelte/elements` or from bits-ui. The **universal three** are `class`, `ref` and `children`.

## In short

- **1,062 API rows** in 262 tables across 70 items. 262 rows are described (25%). 800 are empty. Two items are fully described (EXECUTED). This matches the scorecard's twin count.
- **Two thirds of the empty rows are the universal three:** 504 rows (`ref` 199, `class` 191, `children` 114) that no item declares, plus 20 that an item declares and leaves bare (EXECUTED).
- **The universal three can be described from the template.** A prototype read each component's markup and found the element that `ref` binds, the element `class` reaches and the element `children` renders in. It resolved **513 of 524** rows (EXECUTED).
- **The rest is writing:** 287 rows (143 own members, 109 pass-throughs, 11 unresolved universal rows, 24 module exports), and 74 members of exported object types. **361 comments in all** (EXECUTED).
- **Svelte's tooling shows a comment only when it sits on the props type's member.** svelte2tsx drops a comment written on a destructured binding (EXECUTED). TypeScript shows a re-declared member's comment, with its type unchanged, when the member is typed by indexed access to its source (EXECUTED).
- **Every reference keeps one sentence for shared props, and most keep it apart from the code.** bits-ui hand-writes an API schema beside its types. Carbon writes a sentence per component for `className` and `children`. Nobody generates the element's name from the markup (READ).
- **The `var()` census: 71 references in 352 item files.** 69 resolve to a named source. Two are one dynamic prefix, `"var(--code-" + name + ")"`, in `shiki.ts` (EXECUTED). No reference is undefined today. The test's value is the next misspelling.

## 1. Kuiper's API rows today

`apiTables()` reads an item's files at build time (READ, `src/lib/site/api.server.ts`). For a Svelte component it lists every name in the `$props()` destructuring but the rest element, then every member of the item's own props type that is not destructured. It takes a row's type from the member, or from `WELL_KNOWN` for `class`, `ref`, `children` and `child`. It takes the doc comment only from the member (`doc: m ? JSDOC(m) : ""`). So a pass-through can never carry a comment today. For a `.ts` file it lists each export, with its comment. The closing row ("and every attribute of `<button>`", "and the props of bits-ui's `Dialog.Content`") is written by `inheritsText()`. It is not a row.

The table hides the description column when no row of a table has one (READ, `src/lib/site/page/api-table.svelte`, `018` decision 7).

**By source** (EXECUTED, an instrumented copy of the parser over `registry.json`):

| Where the row comes from | Rows | Empty |
|---|---|---|
| The item's own type member | 346 | 163 |
| `class`, `ref`, `children` with no own member (`WELL_KNOWN`) | 504 | 504 |
| A pass-through from `svelte/elements` or bits-ui | 109 | 109 |
| A module export (lib, hooks, `.ts` files of ui items) | 103 | 24 |
| **All** | **1,062** | **800** |

The 109 pass-throughs are named for a reason. The item sets a default (`sideOffset = 4`, `decorative = true`, `type = "button"`), binds the value (`open = $bindable(false)`), reads it (`href` turns the button into a link), wires it from a field (`id`, `aria-describedby`, `aria-invalid` on `input`, `checkbox`, `switch`, `radio-group`, `native-select`, `input-otp`), or wraps a handler (`onclick` while busy). Each needs a sentence about what Kuiper does with it (EXECUTED, the row list).

**Items with no table:** the theme, the three fonts and `product-home` (EXECUTED). After `020`, the `pluto-theme` alias joins them; it has no files (`020` decision 3).

**Members of exported object types:** 87 exported types and interfaces in item files hold 96 members of object literals or interfaces. 22 are described; 74 are not. They are the shapes an app passes in: `MarketingLink.label`, `SettingsValues.email`, `ChatMessage.role`, `HighlightRange.from` (EXECUTED). They are not API rows. The page shows each type as one module row.

**JSDoc tags:** item source holds none (`@default`, `@param`, `@returns`, `@example`, `@deprecated`, `@see`), and no `@component` comment (EXECUTED, grep). `JSDOC()` keeps only a comment's text, so a tag would never reach the table (READ, `api.server.ts`).

**The voice of the 262 comments** (EXECUTED): median 12 words, 90th percentile 28. No component row runs past 40 words. One does not end with a full stop (`useHighlightedCode`). Two open by repeating their name with a colon ("Busy: the button shows a spinner…", "Disabled: `contenteditable="false"`…"). None starts "This prop", "Specify" or "Used to". They are declarative and short: "The control's id. Without it, the field makes one." (READ, `field.svelte`).

## 2. How Svelte 5 tooling shows a prop's comment

- **svelte2tsx keeps the props type you write, and nothing else.** svelte-check 4.7.7 bundles it. Run on a component with an untyped `$props()`, it generates `type $$ComponentProps = { busy?: boolean, label: any }`. The comment written on the `busy` binding is not in that type. Run on a typed `$props()`, it uses the annotation as the props type; the binding's comment is not part of it (EXECUTED, the bundled `svelte2tsx()` on two scratch components).
- **The language server answers hovers through TypeScript** on that generated code (READ, [language-tools overview](https://github.com/cbartz/language-tools/blob/master/docs/internal/overview.md), a fork of the official repo's doc). So a hover shows the doc comment of the props type's member.
- **A re-declared member shows its own comment, and keeps its type.** With TypeScript 6.0.3's language service, `type Props = Attrs & { /** Renders an a… */ href?: Attrs["href"] }` shows `href?: string | null | undefined` with the new comment. No diagnostic (EXECUTED). Intersecting a member with its own indexed type changes nothing, also over a discriminated union (INFERRED: `(A | B) & { v?: (A | B)["v"] }` distributes, and each branch's `v` narrows back to its own).
- **`svelte/elements` documents none of `class`, `children`, `href` or `disabled`** (EXECUTED, `node_modules/svelte/elements.d.ts`). bits-ui documents some members (`open`, `onOpenChange`, `level`) and none of `ref`, `child` or `children`; its comments sit on generic parameters (EXECUTED, `bits-ui/dist/internal/types.d.ts`, `bits/dialog/types.d.ts`).
- **Svelte's docs do not cover prop comments.** The `$props` and TypeScript pages show typed `Props` interfaces and no comments (READ, [`$props`](https://svelte.dev/docs/svelte/$props), [TypeScript](https://svelte.dev/docs/svelte/typescript)). The FAQ says components and exports are documented with "specially formatted comments", and that a component's needs `@component` (READ, [FAQ](https://svelte.dev/docs/svelte/faq)).
- **Comments can be lost in packaged `.d.ts` files** when props extend another component's through `ComponentProps<>` (READ, [language-tools#2186](https://github.com/sveltejs/language-tools/issues/2186), open). Kuiper ships source, not `.d.ts`, so this does not reach an app (INFERRED).
- **sveld** (Carbon's Svelte doc generator) supports runes `$props()`, and writes defaults as `@default` in its generated types (READ, [sveld](https://github.com/carbon-design-system/sveld)).

## 3. How the references describe props

Clones are under `context/prior_art/` at the commits in its README. Studied, never copied.

| System | Where a prop's sentence lives | Shared props (`class`, `ref`, `children`) | Kept true by |
|---|---|---|---|
| **Carbon** (React) | A doc comment on each member of the props interface, and again on its `propTypes` (READ, `packages/react/src/components/Button/Button.tsx`) | Written per component: "Specify an optional className to be added to your Button" (READ, its `propTypes`) | Nothing joins the two copies (INFERRED) |
| **Carbon**, re-declared HTML props | `href?: React.AnchorHTMLAttributes<HTMLAnchorElement>['href']`, with its own comment (READ, same file, lines 52–55) | | The indexed type keeps it equal to the attribute |
| **Primer** | A hand-kept `*.docs.json` per component (READ, `research/2026-11-15-component-page-standard.md` §2) | In the same file | A schema; not checked against the TypeScript types, so it can drift (READ, same) |
| **Spectrum** | The site's options table is generated from type data (EXECUTED in the page-standard memo, `ComboBox.json`). The design data lists options with an optional `description`: Button has 8 options, 3 described (EXECUTED, `adobe-spectrum-design-data/packages/design-data/components/button.json`) | Not in the design data | Generation from types |
| **Radix Themes** | Runtime prop definitions per component, `*.props.ts(x)`, which spread shared ones (`asChildPropDef`). 12 of 61 props files hold any doc comment (EXECUTED, grep) | Shared definition objects | The definitions drive the component's classes |
| **bits-ui** | A hand-written schema per component, `docs/src/lib/content/api-reference/*.api.ts`, beside its types (READ) | Helpers write one sentence each: `refProp({ elType })`, `childrenSnippet()`, `childSnippet()` (READ, `shared.ts:110–148`) | Nothing joins the schema to the types (INFERRED) |
| **shadcn-svelte** | None. 2 of 394 component files hold a doc comment. A page links to bits-ui's API reference (EXECUTED, grep; READ, `docs/content/components/dialog.md`) | — | — |
| **Atlassian** | Generated from TypeScript; an empty one prints "No description." (READ, page-standard memo §2) | | Generation |

INFERRED:

- **The working pattern is one sentence per shared prop, parametrised.** bits-ui parametrises by element type; Carbon repeats by hand. Kuiper can go one step further and name the element from the item's own markup, so the sentence cannot drift from what renders.
- **Carbon's re-declaration is the pattern for pass-throughs.** It keeps the type the attribute's, and puts the component's own sentence where an editor shows it.
- **Only generation from source avoids drift.** Primer and bits-ui keep a second copy. Kuiper's tables are already parsed from source; the comments should be too.

## 4. The universal three, from the template

A prototype walked each component's markup with `svelte/compiler`'s modern AST (EXECUTED, scratch script):

- `ref`: the element or component that carries `bind:this={ref}` or `bind:ref={ref}`;
- `class`: the element or component whose `class` expression names the destructured local (`class: className`);
- `children`: the nearest element or component around `{@render children…}`.

**Result:** 513 of the 524 bare universal rows resolve (EXECUTED). Five resolve to two targets: `Button`'s `ref`, `class` and `children` (`<a>` or `<button>`), `Sidebar.children` (`<nav>` or `<div>`), and the app shell layout's `children` (`<div>` or `<main>`). Eleven do not resolve. In nine, `class` reaches the element through a computed props object handed to a `child` snippet (`Item`, `Marker`, `Lockup`, `BreadcrumbLink`, five sidebar parts). In two, `children` renders inside a snippet that bits-ui calls (`DropdownMenuCheckboxItem`, `DropdownMenuRadioItem`).

For a bits-ui or Kuiper component as the target, the sentence names that component. Its import gives the public name: `DialogPrimitive.Content` is bits-ui's `Dialog.Content`. `inheritsText()` already does this for the closing row (READ).

## 5. `var()` in item files

A scan of the 352 files that `registry.json` lists for items (EXECUTED, scratch script; the same set as `literals.test.ts`'s `FILE_COUNT`):

- **71 references**: `var(--x)` anywhere, and Tailwind's shorthand `utility-(--x)`. One has a fallback: `rounded-[var(--radius-action,var(--radius))]` in `button`.
- **Where each name is defined:**

| Source | References |
|---|---|
| The theme item's `css` (`:root`, `.dark` and the rest) in `registry.json` | 36 |
| The theme item's `cssVars.light` (and `dark`) | 16 |
| The theme item's `cssVars.theme` (Tailwind's `@theme inline`) | 8 |
| bits-ui, at run time | 6 |
| Tailwind's default theme (`--container-3xs`, in `composer`) | 2 |
| A font item's `font.variable` (`--font-mono`, in `code-editor-theme.ts`) | 1 |
| A dynamic prefix: `"var(--code-" + name + ")"` in `lib/highlight/shiki.ts` | 2 |

- **bits-ui builds its names at run time.** Its dist holds the literal `--bits-floating-transform-origin` and the template `` `--bits-${name}-content-transform-origin` `` (EXECUTED, grep of `node_modules/bits-ui/dist`). The items read the expanded names, such as `--bits-popover-content-transform-origin` (EXECUTED). So a check must match bits-ui's templates, not only its literals.
- **The dynamic prefix expands over `CODE_ROLES`,** exported by `lib/highlight/roles.ts` (EXECUTED).
- **`@theme inline` names are not always emitted.** `002` found that `var(--ease-entrance)` would be undefined at run time, since Tailwind inlined the value (READ, `002`, "Why the curve is written out"). `004`'s review found that `@theme inline` names read by `var()` in a scanned file do resolve (READ, `reviews/004-code-and-data-spec-2026-10-31.md` item 18, EXECUTED there). `composer.svelte`'s comment relies on the same thing: "The composer's file must be among Tailwind's sources, so that max-h-(--container-3xs) emits its variable" (READ). INFERRED: a name in `@theme` or `@theme inline` resolves when the file that names it is one of Tailwind's sources, which an app's `src/lib` is by default. A probe with Tailwind's `compile()`, as `020`'s review ran, would settle it (not run here: this memo runs no build).
- **A misspelled name fails silently.** An undefined `var()` radius computes to `0px` (READ, `reviews/009-expressive-mode-and-the-brand-slots-spec-2026-11-01.md`, EXECUTED there). A fallback hides a misspelling completely (INFERRED, *Material* idea 2).

## 6. What the doc comments cost the site

- **A sentence is sent twice on a first load.** On the built Button page, `busy`'s sentence appears twice in `index.html`: in the cell and in the inline hydration data. It appears once more in `__data.json`, which a client-side navigation fetches (EXECUTED, `build/components/button/`, built 2026-11-15 16:10).
- **Button would gain about 0.4 kB gzipped.** Nine drafted sentences, each inserted twice into the built `index.html`, raised its gzipped size from 25,635 to 26,064 bytes (EXECUTED). Dialog has 21 empty rows, `sidebar` 78 (EXECUTED); about 1 kB and 3 to 4 kB (INFERRED, by proportion).
- **Button has no headroom.** It transfers 380 kB against a 380 kB budget (READ, `specifications/024-budgets-per-template.md`). `024` raises the component template to about 450 kB, and requires a change that adds weight to every page of a template to state it (READ, `024`).

## 7. What this suggests

INFERRED, for `023` to decide:

1. Write comments on the props type's members, never on the binding.
2. Re-declare each pass-through in the item's own type, typed by indexed access to its source.
3. Describe the universal three from the template, with one fixed sentence each. An item's own comment wins. A row the template cannot resolve gets a hand comment.
4. Leave bits-ui's own comments in bits-ui. Kuiper's sentence says what Kuiper does.
5. Test every row and every exported member, for presence and for the countable parts of the voice.
6. Test `var()` against the theme item, the font items, Tailwind's default theme, the same file, bits-ui's own templates, and one declared dynamic prefix.
7. Land after `024`, which gives Button room.

## 8. Corrections, 2026-11-15, after the specification review

The memo above stands as first written. These corrections come from [the review of `023`](../reviews/023-prop-doc-comments-spec-2026-11-15.md), whose probes are cited as EXECUTED (review), and from re-running this memo's scripts (EXECUTED). Where they differ, this section governs.

1. **§2, svelte2tsx.** "Drops a comment on a destructured binding" is loose. svelte2tsx keeps the comment in its output, at the binding, but in no type, so no hover shows it (EXECUTED (review): a consumer's hover over a binding-commented `href` shows no comment). The conclusion stands: the comment belongs on the type's member.
2. **§2, "equal" types.** `X & { k?: X["k"] }` is mutually assignable with `X`, not identical: TypeScript's strict identity check is false (EXECUTED (review), `tsc` over the real `svelte/elements` and bits-ui types). In a union, a member's hover text changes: `ToggleGroup`'s `multiple` `value` reads `string[] | (string[] & string) | undefined` (EXECUTED (review)).
3. **§2, the hover.** When bits-ui's member has its own comment, a re-declared member's hover shows bits-ui's text, then Kuiper's (EXECUTED (review), `Dialog.RootProps["open"]`).
4. **§4, the generator's counts.** 513 and 11 came from a prototype whose rules were not all written down. Under rules stated in full, 495 rows fill and 29 are left (EXECUTED, `gen2.ts`). The rules: distinct names joined, more than two unfilled; `<svelte:element>` (17 rows) and third-party components (1) unnamed; a namespaced Kuiper part named by its namespace; `cn(<local>)` alone read as plain; a `{#snippet}` boundary stops the `children` walk. The 29 left are 17 `<svelte:element>`, 9 `class` through a `child` snippet, 2 `children` behind a snippet boundary, and 1 `phosphor-svelte` target.
5. **§1, the hand total.** With those 29, hand-written API rows are 305: 143 own, 109 pass-throughs, 29 universal, 24 module exports. Members of exported types are 96, not 74. Object literals inside exported unions and intersections add 22 bare members (EXECUTED, `types2.ts`): 21 in `SignInResult`, `SignUpResult`, `SignUpCodeResult`, `SettingsResult` and `ChatSegment`, and `utils`' `WithElementRef.ref`. The members of a `…Props` alias that are also API rows are not counted. **All hand comments: 401.**
6. **§1, pass-throughs.** 4 of the 109 come from another item, `toggle`'s `ToggleVariants`, not from `svelte/elements` or bits-ui (EXECUTED (review)).
7. **§3 and §7, `cn`.** `cn` resolves a conflict only between utilities it knows. It keeps the theme's own beside an app's: `cn("rounded-action", "rounded-lg")` and `cn("groove-b", "border-b-0")` return both (EXECUTED (review); `001` decision 10 found the same). So no generated sentence may say an app's class wins.
8. **§5, the census.** It missed Tailwind's typed shorthand `utility-(length:--x)`. Adding it gives **80 references**: theme `css` 45, `cssVars.light` 16, `cssVars.theme` 8, bits-ui 6, Tailwind's default theme 2, a font variable 1, the dynamic prefix 2 (EXECUTED, `vars3.ts`). No reference resolves by "the same file". The nine typed ones are `border-b-(length:--focus-width)` 8 times and `text-(length:--mark-lockup-size)` once.
9. **§5, bits-ui's names.** bits-ui expands its five floating templates in `getFloatingContentCSSVars(name)` (`internal/floating-svelte/floating-utils.svelte.js`) over the literal arguments `tooltip`, `menubar`, `dropdown-menu`, `context-menu`, `popover`, `menu` and `link-preview` (EXECUTED, grep). A check should expand over those arguments and match whole names. A substring or any-name match lets a typo pass.
10. **§5, `@theme inline`.** The `cssVars.theme` names items read are `--radius`, `--spacing`, `--text-sm` and `--text-sm--line-height`, all from `code-editor-theme.ts`. `--font-mono` is a font item's variable, not a `cssVars.theme` name. Tailwind's default-theme names (`--container-3xs`) are emitted only on use too. Tailwind's `compile()` reads no files, so a probe must scan sources first, with `@tailwindcss/oxide`'s `Scanner` (EXECUTED (review); present in `node_modules`, EXECUTED).
11. **§6, the weight.** The memo used gzip level 9 through Python. The review's simulation, with longer drafted sentences, gave +656 bytes on Button where this memo gave +429 (EXECUTED (review)). Read Button's cost as 0.4 to 0.7 kB. A `generated` flag in each row's data would add about 14 bytes (EXECUTED (review)). `sidebar`, with 78 empty rows, is about 4 to 6 kB, not 3 to 4 (INFERRED). `024` now raises Button's transfer budget to between 430 and 480 kB (READ, `024`).

No code was copied from prior art. Nothing in the repository was changed but this memo.
