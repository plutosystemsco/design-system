### 3.3 Rules that clash with recorded decisions or with the tools

- **`svelte/no-navigation-without-resolve`, 107.** It wants every internal `href` and `goto()` wrapped in `$app/paths`'s `resolve()`. The site sets no base path (`vite.config.ts`: `paths: { relative: false }`, no `base`), so `resolve()` would change no URL (READ). Items take their `href` from a prop; `ui` items import nothing from `$app` (EXECUTED: `grep`). shadcn-svelte's own button fails it (EXECUTED: its `button.svelte`, linted in the scratch kit, reports line 63), and shadcn-svelte turns the rule off (READ, `eslint.config.js`).
- **`svelte/no-useless-mustaches`, 9.** Most are needed. `{"<Stage>"}` and `{'<main …>'}` keep `<` out of the markup; `{"first\nlast"}` carries an escape; `{'print("hello")'}` carries quotes. The rest are `{" "}`, which `prettier-plugin-svelte` writes to keep a space across a line break (READ: Prettier passes on them). The rule fights the formatter. shadcn-svelte demotes it to a warning (READ).
- **`no-empty-pattern`, 4.** Playwright reads a fixture's first parameter as a destructuring pattern, so `({}, info)` is required. ESLint's own option, `allowObjectPatternsAsParameters`, allows it (EXECUTED: all 4 cleared).
- **`svelte/no-unused-svelte-ignore` on `toaster.svelte:522`, 13.** The comment is `svelte-ignore a11y_no_noninteractive_element_interactions: its keys and pointer pauses are …`. Svelte 5 reads it right: in runes mode, codes end at the first one not followed by a comma, and "everything after is interpreted as prose" (READ, `svelte/src/compiler/utils/extract_svelte_ignore.js`). The plugin reads each word of the reason as a code. With the reason moved to its own comment just before, Svelte still applies the ignore (EXECUTED: compiled, no warning; with the ignore removed, the warning returns at line 524) and the plugin is satisfied.
- **The other 4 `no-unused-svelte-ignore` findings are real** (EXECUTED). With the ignores removed, Svelte 5.57.3 emits no warning for `input-group-addon.svelte:44`, `pagination.svelte:269` (both codes) or `tag-group.svelte:70`. They are stale.
- **`no-useless-assignment` on `settings-form.svelte:75`.** `dirty = $bindable(false)` is a bindable prop's default. A bound parent reads it before the component's effect writes `dirty` (the review's S1). ESLint sees only the component, so it calls the default unused (INFERRED). The other four are real: an initial value every path overwrites.
- **`no-explicit-any`, 25.** None looks like a mistake (INFERRED). The review counts `any` as rare (T3): `Component<any>` for example modules, `(window as any)` page hooks in `code.spec.ts`, untyped registry `meta` in `registry.test.ts`, YAML in `scripts/ci/workflow.ts`. `strict` already forbids an implicit `any`. In items, the rule matters: the stock chart's three `eslint-disable` comments name it, and an app's lint runs it (§5).
- **The ledger's `test.fail`, the test views and `listed-items.ts`: no clash** (EXECUTED). No rule in these sets reads `test.fail`. The test views under `src/routes/(view)/` had one finding, a mustache. `src/lib/site/listed-items.ts` and the other generated sources pass as generated.
- **The stock chart's `eslint-disable` comments are used** (EXECUTED). `chart-tooltip.svelte:12` and `:56` and `chart-utils.ts:27` each silence a `no-explicit-any` that would fire. With `reportUnusedDisableDirectives` an error, they stay right only while that rule runs on items.
- **A test fixture under test.** `tests/unit/fixtures/api/snippet-boundary.svelte` has a children snippet the rule calls useless. The snippet boundary is what the fixture tests (READ). Fixtures are inputs, not code we maintain.
