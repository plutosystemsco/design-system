2. **Medium — The fence splitter turns a fence whose info string is not a single `\w+` run into prose, and its closing fence then opens an empty block that swallows the rest of the reply** (`src/lib/registry/components/chat-text.svelte:18`; decision 10).
   Failure: the opener is `/^```(\w*)\s*$/`. EXECUTED on a verbatim copy: "```c++" and "```python title=x" are not fences, so the line and the code become one prose paragraph (the backticks visible), and the bare "```" that was meant to close becomes an opener, leaving an empty `code-block` headed "code" to the end of the string; while inside a block, a "```js" line closes it (CommonMark treats an info string on a closer as content). Hyphenated and symbolled ids are common in model replies (`shell-session`, `objective-c`, `c++`, `c#`), and the failure is not local: the fence state is inverted for the rest of the message. Also EXECUTED: CRLF text keeps `\r` at every code line's end (the highlighter and the copy button receive it); prose is unaffected since `paragraphs()` trims. An unclosed fence, a language-less fence, trailing spaces on a closer, four backticks, an indented fence and inline backticks behave acceptably.
   Fix: an opener is `/^```\s*([^\s`]*)/` (take the first word of the info string as the language, ignore the rest); inside a block, only a line that is backticks alone (`/^```\s*$/`) closes; strip a trailing `\r` from each line (`text.split(/\r?\n/)`).
