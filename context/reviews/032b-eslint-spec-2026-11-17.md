## Findings, most severe first

1. **Medium: the item bar compares levels, not options. So "passing our lint means passing shadcn-svelte's" is not true, and the test as written also fails on `.ts` files** (decision 7, the item-bar test, criterion 5).
   - EXECUTED, with `lintText` on `src/lib/registry/lib/planted.ts`:
     - `const { a, ...rest } = o; return rest;` passes ours. It fails shadcn-svelte's set and the stock set. The cause is `ignoreRestSiblings: true`.
     - `catch (_e)` passes ours. It fails shadcn-svelte's set and the stock set. The cause is `caughtErrorsIgnorePattern: "^_"`.
     - `const [_a, b] = x` passes ours and shadcn-svelte's set. It fails the stock set. The cause is `destructuredArrayIgnorePattern`.
   - The planned test reads only each rule's level. `@typescript-eslint/no-unused-vars` is `error` in both, so it cannot see the looser options. The same blind spot would let a later edit weaken any rule on items through its options.
   - EXECUTED: `calculateConfigForFile` gives three weaker rules on `button.svelte`: `no-undef`, `svelte/no-navigation-without-resolve` and `svelte/no-useless-mustaches`. On `chart-utils.ts` and `toast-queue.ts` it gives two, because `ts.configs.recommended` already turns `no-undef` off for `.ts` files. "Exactly these three" per file fails on two of the spec's three files.
   - EXECUTED: with `ignoreRestSiblings` and `caughtErrorsIgnorePattern` removed, the fixed tree still lints with 0 findings. Nothing needs them today.
   - Fix:
     - Drop `ignoreRestSiblings` and `caughtErrorsIgnorePattern` from decision 4 and the config. Keep `destructuredArrayIgnorePattern`, since shadcn-svelte's set allows `_` names too.
     - The item-bar test also checks `no-unused-vars`'s options on item files against shadcn-svelte's, by named fields. These are `args`, `caughtErrors`, `ignoreRestSiblings`, and the patterns, which may only be `^_` where shadcn-svelte's set allows it.
     - The exception list is checked over the union of the three files: it must be exactly the three rules. Each file's own list must be a subset of them.
