1. **Medium — The roles plugin does not rebuild when the parse tree grows, so below the first 3,000 characters of a document shown at load a built-in reads as a call, a `self` as a name and a docstring as a string, until the viewport or the document changes** (`src/lib/registry/ui/code-editor/code-editor-python.ts:143-146`, the `update` method; decision 6).
   Failure: `update()` rebuilds on `docChanged || viewportChanged` only. A fresh state parses 3,000 characters within 20 ms at creation (READ, `LanguageState.init`); the rest is parsed in idle time and arrives as a state effect with no document or viewport change. CodeMirror's own highlighter rebuilds on that effect (READ, `TreeHighlighter.update`: `tree != this.tree`); the plugin ignores it. EXECUTED (`probe3.ts`, the editor page's view given a fresh state of 40 lines of 180 characters, 7,180 in all, with the visible range 0 to 6,459): at once, lines 2 to 16 (under 3,000 characters) read `print[ͼb] print[text-code-builtin]` and lines 20 and 30 read no spans; after 2.5 s lines 20 and 30 read `print[ͼb] len[ͼb]`, the highlighter's amber call colour, with **no `text-code-builtin`**; after a 40 px wheel the same. Any document whose visible text at load exceeds 3,000 characters shows it: wide lines, a tall editor (the component grows with its document), or `reset()` into one. The first app's run panel opens on a file.
   Fix: keep the tree the way `TreeHighlighter` does: store `this.tree = syntaxTree(view.state)` in the constructor and in `update()` rebuild when `update.docChanged || update.viewportChanged || syntaxTree(update.state) != this.tree`. Add to E3 a reading on a long document: set a 40-line, 180-character document through `reset()`, wait for the parse, and read `text-code-builtin` on the last line's `print` without a scroll.

2. **Medium — A docstring after a shebang, a licence comment or a same-line comment reads as a string** (`code-editor-python.ts:180-183`, `isDocstring`; decision 6).
   Failure: the function takes the scope's first child, skipping only `:`, and compares it to the statement. A `Comment` node precedes the first statement whenever the file opens with `#!…` or `# SPDX…`, or a `def` line ends in a comment (EXECUTED, `arglist.ts`: `Script: Comment'#!/usr/bin/env python' ExpressionStatement'"""Doc."""'`). EXECUTED in the editor (`probe2.ts`, B1): `#!/usr/bin/env python` then `"""Module docstring."""` renders `"""Module docstring."""[ͼ6]`, the string class alone; `walk.ts` case 3 shows the same for `def g():  # trailing comment` followed by its docstring. The class sample, which opens on its docstring, does not reach it. Python's own rule is the first *statement*; comments are not statements.
   Fix: `while (first && (first.name === ":" || first.name === "Comment")) first = first.nextSibling;`. Add the shebang form to E3's docstring reading.

3. **Medium — A keyword argument whose name is a built-in's is coloured as a built-in in a call, where decision 2 keeps keyword arguments in the body and the block does** (`code-editor-python.ts:156-162`; decisions 2 and 6: "Keyword arguments stay in the body on both engines").
   Failure: the plugin skips a `VariableName` under `ParamList`, `TypeDef` and `Decorator` and marks every other name on the list.    Fix: in `enter`, before the built-in check, `if (parent?.name === "ArgList" && ref.node.nextSibling?.name === "AssignOp") return;`. Add `sorted(runs, key=len)`'s shape with a built-in name, `f(type=1)`, to E3 and read the body colour on `type`.
